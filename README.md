## Overview

IndicMT is a **153.8M-parameter Transformer** (12 encoder + 12 decoder layers) that translates between English and 22
Indian languages, 44 directions in all. It is trained from scratch on AI4Bharat's BPCC data, with one 128k SentencePiece
vocabulary and a target-language tag at the start of each source sentence. It is converted to CTranslate2 and served on
**CPU with int8 weights (170.6 MB)** behind a FastAPI backend and a plain HTML/JS frontend. Translation between two Indian
languages goes through English.

This repository holds the whole pipeline: data preparation, mixing, tokenizer, training, fine-tuning, evaluation,
quantization and serving. It contains code, configs and documentation only. Data, models and results are generated by the
scripts and are not stored here.

## Results

Current best model: 12+12 layers, pre-trained on the combined 8:2 (mined to human) data (best checkpoint, step 13,600), then
fine-tuned on human data without replay (best checkpoint, step 1,800). Macro average over the 22 languages, chrF++, with
**CPU inference** (CTranslate2 float32, beam 5):

| Test set | en→xx | xx→en |
|---|---:|---:|
| IN22-Gen | **46.04** | **53.87** |
| IN22-Conv | 41.06* | 50.04* |

\* IN22-Conv was scored only through OpenNMT-py (`onmt_translate`, beam 5). Through OpenNMT-py the same checkpoint scores
45.36 / 53.73 on IN22-Gen; every checkpoint comparison during training used that path.

- **chrF++** is a character n-gram F-score. Higher is better. BLEU for the same model with CPU inference: IN22-Gen 16.11
  (en→xx) and 28.82 (xx→en); IN22-Conv 13.01 and 27.62 (OpenNMT-py).
- Against 12 published systems on IN22-Gen, IndicMT ranks **5th of 13** on the two-direction mean and **4th on en→xx**, with
  far fewer parameters (0.154B, against 1.1B to 30.7B). The comparison is indicative: the baselines are published
  sentence-level, greedy-decoding scores, and ours are corpus-level with beam 5.
- **LLM judge** (Gemma 4 31B-it, English to Indic, 55,594 sentences): **46.7%** of translations are rated perfect (5/5/5) on
  fluency, adequacy and overall, against about 79% for the human references.
- **int8 quantization** costs 0.13 chrF++ (en→xx) and 0.06 (xx→en) against float32, and makes the model 3.7 times smaller.

> [!WARNING]
> **Caveats.** All results are from a **single seed**. The checkpoint was **selected using the IN22 test sets**, so the IN22
> scores carry a small optimistic bias. The release model will be chosen after the deeper architectures (12+18, 18+18) finish
> fine-tuning; numbers here will be updated then.

## Quick start

### Train from scratch

```bash
# 1. Install the full environment (torch must match your CUDA build; see the comment in requirements-train.txt)
pip install -r requirements-train.txt

# 2. Data (BPCC and IN22 are gated: request access on Hugging Face first)
export HF_TOKEN=<your token>
python data/bpcc-human/download_bpcc_human.py
python data/bpcc-mined/download_bpcc_mined.py
python data/in22/download_in22.py
python data/bpcc-human/create_splits.py

# 3. Each later stage runs locally or as a batch job from scripts/slurm/
mkdir -p logs
sbatch -p <partition> scripts/slurm/data_human_multilingual_dataset.sh      # Job1; see scripts/README.md for Job2 onwards
```

> [!IMPORTANT]
> BPCC and IN22 are gated datasets: request access on Hugging Face before running the download scripts.

Follow the READMEs in order: `data/`, `mixing/`, `tokenizer/`, `training/`, `evaluation/`, `deployment/`.

> [!TIP]
> Training the full set of models takes days on 4 A100 GPUs, so most readers will want the released weights instead.

### Translate with the released model

Weights at `<WEIGHTS_URL>`.

```bash
# minimal CPU environment: no PyTorch or OpenNMT-py needed
pip install -r requirements-deploy.txt
# stage the int8 CTranslate2 model and tokenizer as described in deployment/README.md, then:
uvicorn deployment.api.main:app --port 8000
curl -X POST localhost:8000/api/translate -H "Content-Type: application/json" \
  -d '{"text":"Hello, how are you?","source_lang":"en","target_lang":"hi"}'
```

Open `http://localhost:8000/` for the web interface.
