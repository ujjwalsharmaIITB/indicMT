## Overview

IndicMT is a **153.8M-parameter Transformer** (12 encoder + 12 decoder layers) that translates between English and 22
Indian languages, 44 directions in all. It is trained from scratch on AI4Bharat's BPCC data, with one 128k SentencePiece
vocabulary and a target-language tag at the start of each source sentence. It is converted to CTranslate2 and served on
**CPU with int8 weights (170.6 MB)** behind a FastAPI backend and a plain HTML/JS frontend. Translation between two Indian
languages goes through English.

This repository holds the whole pipeline: data preparation, mixing, tokenizer, training, fine-tuning, evaluation,
quantization and serving. It contains code, configs and documentation only. Data, models and results are generated by the
scripts and are not stored here.

## Results

<p align="center"><img src="docs/images/in22-gen-comparision-chart.png" alt="IN22-Gen English to Indic chrF++: IndicMT 47.15 against other systems" width="100%"/></p>

Release model: 12+12 layers, pre-trained on the combined 8:2 (mined to human) data (step 13,600), then fine-tuned on
human data without replay (step 1,800). Macro average over the 22 languages, chrF++, **CTranslate2 float32 model**
(beam 5; see [Quantization and the reported model](#quantization-and-the-reported-model)):

| Test set | en→xx | xx→en |
|---|---:|---:|
| IN22-Gen | **47.15** | **53.87** |
| IN22-Conv | **43.15** | **50.59** |

- **chrF++** is a character n-gram F-score. Higher is better. BLEU for the same model: IN22-Gen 19.19 (en→xx) and
  29.19 (xx→en); IN22-Conv 15.73 and 28.36.
- **Against IndicTrans2 1B under the same protocol** (paired bootstrap, 22 directions pooled): IndicMT is slightly but
  significantly ahead on en→xx on IN22-Gen (47.31 against 46.53, p = 0.001; 11 directions better, 8 worse at
  p < 0.05) and on IN22-Conv (43.23 against 42.60, p = 0.001; 8 better, 13 worse). IndicTrans2 is clearly ahead on xx→en (62.48 against 53.87 on IN22-Gen,
  55.63 against 50.59 on IN22-Conv) and has 1.1B parameters, 7.2 times more than IndicMT.
- **LLM judge** (Gemma 4 31B-it, en→xx, IN22-Gen, 22,528 sentences): shown the human reference, the judge rates
  **63.8%** of IndicMT translations perfect (5/5/5 on fluency, adequacy and overall; mean overall 4.33 of 5), against
  70.3% (4.48) for IndicTrans2 1B. Without the reference: 66.9% (4.38) against 73.8% (4.52).

### Quantization and the reported model

**All results on this page are from the CTranslate2 float32 model**, the release checkpoint (OpenNMT-py step 1,800)
converted to CTranslate2 without quantization. The Hugging Face repository ships the OpenNMT-py checkpoint and the int8
CTranslate2 model. chrF++, beam 5; latency is the median for one sentence on CPU (8 threads), IN22-Gen.

| Model | IN22-Gen en→xx | IN22-Gen xx→en | IN22-Conv en→xx | IN22-Conv xx→en | p50 latency | Size |
|---|---:|---:|---:|---:|---:|---:|
| OpenNMT-py checkpoint (`onmt_translate`) | 46.95 | 53.69 | 42.97 | 50.38 | | 2.4 GB |
| **CTranslate2 float32 (reported)** | **47.15** | **53.87** | **43.15** | **50.59** | 399.2 ms | 630.4 MB |
| CTranslate2 int16 | 47.15 | 53.86 | 43.15 | 50.59 | 367.1 ms | 323.2 MB |
| CTranslate2 int8 (released) | 47.16 | 53.85 | 43.14 | 50.59 | 374.2 ms | 170.6 MB |

The checkpoint and the CTranslate2 float32 model have the same weights; their scores differ by about 0.2 chrF++
because the two decoders differ. int16 and int8 are **not significantly different from float32** on IN22-Gen (paired
bootstrap, pooled p = 0.18 en→xx and 0.15 xx→en for int8; 0 of 22 directions after Bonferroni correction). int8 is
3.7 times smaller than float32. The checkpoint's size includes the optimizer state.

## How the pieces fit

```mermaid
flowchart LR
    A[BPCC data<br/>download, filter, split] --> B[Mixing<br/>temperature sampling]
    A --> C[Tokenizer<br/>SentencePiece 128k]
    B --> D[Training data<br/>build and encode]
    C --> D
    D --> E[Pre-training<br/>human / mined / combined]
    E --> F[Fine-tuning<br/>human data]
    F --> G[Evaluation<br/>chrF++, BLEU, LLM judge]
    F --> H[CTranslate2<br/>float32, int16, int8]
    H --> I[API + frontend<br/>CPU, int8]

    classDef data fill:#C4B5FD,stroke:#7C3AED,stroke-width:2px,color:#1C1535
    classDef train fill:#A855F7,stroke:#6D28D9,stroke-width:2px,color:#FFFFFF
    classDef eval fill:#EC4899,stroke:#BE185D,stroke-width:2px,color:#FFFFFF
    classDef serve fill:#4F46E5,stroke:#3730A3,stroke-width:2px,color:#FFFFFF
    class A,B,C,D data
    class E,F train
    class G eval
    class H,I serve
```

Colours: lavender for data preparation, purple for training, pink for evaluation, indigo for conversion and serving.
Plain text: data → mixing → tokenizer → training data → pre-training → fine-tuning → evaluation, and fine-tuning →
CTranslate2 conversion and quantization → API and frontend.

## Quick start

### Train from scratch

```bash
# 1. Install the full environment (torch must match your CUDA build; see the comment in requirements-train.txt)
pip install -r requirements-train.txt

# 2. Data (BPCC and IN22 are gated: request access on Hugging Face first)
export HF_TOKEN=<your token>
python data/bpcc-human/download_bpcc_human.py
python data/bpcc-mined/download_bpcc_mined.py
python data/in22/download_in22.py
python data/bpcc-human/create_splits.py

# 3. Each later stage runs locally or as a batch job from scripts/slurm/
mkdir -p logs
sbatch -p <partition> scripts/slurm/data_human_multilingual_dataset.sh      # Job1; see scripts/README.md for Job2 onwards
```

> [!IMPORTANT]
> BPCC and IN22 are gated datasets: request access on Hugging Face before running the download scripts.

Follow the READMEs in order: `data/`, `mixing/`, `tokenizer/`, `training/`, `evaluation/`, `deployment/`.

> [!TIP]
> Training the release model takes about 110 A100 GPU-hours (see [Compute](#compute)), so most readers will want the released weights instead.

### Translate with the released model

Weights: [ujjwalsharmaIITB/indicMT](https://huggingface.co/ujjwalsharmaIITB/indicMT) on Hugging Face, with the OpenNMT-py checkpoint (`indicMT.pt`), the int8 CTranslate2 model (`indicMT/`) and the tokenizer (`indicMT.spm.model`). Its model card, with examples for both models that encode inputs exactly as in training, is kept here as [`huggingface/README.md`](huggingface/README.md).

```bash
# minimal CPU environment: no PyTorch or OpenNMT-py needed
pip install -r requirements-deploy.txt
# stage the int8 CTranslate2 model and tokenizer as described in deployment/README.md, then:
uvicorn deployment.api.main:app --port 8000
curl -X POST localhost:8000/api/translate -H "Content-Type: application/json" \
  -d '{"text":"Hello, how are you?","source_lang":"en","target_lang":"hi"}'
```

Open `http://localhost:8000/` for the web interface.

## Compute

GPU-hours are GPUs × wall-clock hours, from the cluster's job accounting. Training ran on 4 × A100 80 GB; evaluation and the LLM judge ran on A40 and L40 GPUs.

**Release model only.** What it takes to reproduce the released model:

| Stage | GPUs | GPU-hours |
|---|---|---:|
| Pre-training, combined data, to step 13,600 | 4 × A100 | 100 |
| Fine-tuning on human data, to step 1,800 | 4 × A100 | 11 |
| IN22-Gen and IN22-Conv evaluation of one checkpoint, 88 directions, OpenNMT-py | 2 × A40 | 0.5 |
| chrF++ trajectory: the same evaluation for 63 checkpoints (54 pre-training up to step 13,600, 9 fine-tuning up to step 1,800) | 2 × A40 | 32 |
| IN22-Gen and IN22-Conv evaluation, CTranslate2 float32 (reported scores) | CPU, 16 cores | 0 (about 1 hour) |
| LLM judge, English→Indic | 2 × A40 | 7.7 |
| **Total** (the trajectory includes the single checkpoint) | | **about 150** |

**Whole project.** Everything run for IndicMT, including models that were not released:

| Work | GPU-hours |
|---|---:|
| Pre-training (human, mined and combined data) | 1,539 |
| Deeper architectures (12+18 and 18+18 layers) | 715 |
| IN22 evaluation of checkpoints | 473 |
| Fine-tuning (with and without replay, deeper models) | 248 |
| LLM judge | 135 |
| Baseline runs (IndicTrans2, Indic Translate, Sarvam Translate) | 15 |
| Setup and tests | 4 |
| **Total** | **3,129** |

By GPU type: 2,507 A100, 479 A40, 143 L40.
